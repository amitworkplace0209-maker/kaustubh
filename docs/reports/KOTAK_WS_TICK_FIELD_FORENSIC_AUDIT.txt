2. EXACT WS IMPLEMENTATION
================================================================================
Architecture (one owner, one hook, one canonical stream) - DOCUMENTED + code:
  - Single socket owner: ws_socket/ws_manager.py  WebSocketManager (module
    singleton `ws_manager`, ws_manager.py:2040). Never a second socket.
  - Single engine: ws_socket/engine/engine.py    WebSocketEngine (singleton
    `engine`, engine.py:857). Composes the manager; opens no socket.
  - Wiring: api/ws_engine.py:36-52 `_get_engine()` runs
      engine.set_owner(ws_manager)
      ws_manager.set_publish_hook(engine.on_feed_message)
    once at app startup / lazily. Only place the hook is attached.
  - Feed reader: ws_manager.py:922 `_reader_loop(ws)` async-iterates the SDK
    websocket (`async for message in ws`) -> `_handle_feed_message` (1129).
  - Message dispatch (ws_manager.py:1153-1183):
      SFeedMarketStatus -> counts only, logged, NOT a tick (return).
      SFeedIndex       -> `_process_tick` (valid data tick).
      SFeedCasChange   -> counts only, returned (not a tick).
      SFeedScrip/Lite  -> `_process_tick`.
    For every message the engine hook fires first (1143-1151), so the engine
    sees ALL message types, then each layer classifies independently.
  - Subscribe path: subscribe() (ws_manager.py:1257) -> `_send_subscribe`
    (2012) groups intents via `_group_intents` (1990) into:
      scrips  -> ws.subscribe_scrips(WsToken)  (wire "subscribeScrips",  L4)
      indices -> ws.subscribe_index(...)       (wire "subscribeIndices", 7207)
      depths  -> ws.subscribe_depth(...)       (wire "subscribeDepth",  L8)
    No call to subscribe_full_depth (L16) and none to subscribe_scrips_lite.
  - Unsubscribe path: unsubscribe() (1475) -> `_send_unsubscribe` (2022), SDK
    unsubscribe_scrips/unsubscribe_index/unsubscribe_depth.
  - Supervisor/backoff: ws_manager.py:424-598 (states, market-window gate,
    internet check, reconnect backoff, auth handling). max_reconnect_attempts
    = 0 / max_connect_retries = 0 so OUR supervisor owns the lifecycle
    (1366-1381). Connection created via client.create_websocket (1378).
  - Engine ingress: engine.on_feed_message(message) (engine.py:101):
      TICK_RECEIVED event -> canonicalize() (119) -> TICK_REJECTED or
      TICK_VALIDATED (`_flat_tick`, engine.py:133,270) -> raw bucket ->
      router.route (179) -> data_saver consumer (61-66).
  - Persistence consumer: registered at engine construction as
    data_saver / DATA_SAVER / FULL_RAW / P0 (engine.py:61-66). Drained by
    ConnectionManager._drain_persistence (connection_engine.py:711-761) ->
    to_storage_doc -> DBWriterEngine.ingest -> tick_buffer -> Mongo.
  - Engine event-bus bridge: engine.py:229 `_drain_event_loop` publishes
    TICK_RECEIVED / TICK_VALIDATED / TICK_REJECTED (sole source).

4. RAW TICK MESSAGE FORMAT (wire, SDK protocol.py)
================================================================================
Transport   : native_batch over wss://sfeed.kotaksecurities.com/apifeed
              (SDK audit [S17]) ; frames are length-prefixed packets.
Frame split : protocol.py:82 split_batch() reads u16 LE length prefix.
Header      : 9 bytes, protocol.py:53 _HEADER "<HHbBBBB":
                message_length u16 | message_code u16 | exchange_id i8 |
                level u8 | auction_flag u8 | seq_no u8 | bitmask_length u8
Message codes (protocol.py:30-48):
  1117/1119 auth response | 1109 subscribe ack (JSON, trading_symbols map) |
  6511 market open | 6521 market close | 7207 index | 7208 market picture |
  105  market status (body) | 104  CAS change
Bodies (protocol.py:56-79):
  _INDEX_BODY       "<IiiiiiQiiidBi21s"  (14 scalar fields)
  _MINI_BODY        "<IqIqIiiIBI"        (MiniTouchLine, level 1)
  _MP_BODY          "<IqqqqqIIIIIqIIIIhiIdiIIIIIBI"  (MarketPicture 135 B)
  _DEPTH_ROW        "<qii"               (16 B: qty/price/orders)
  _MARKET_STATUS_BODY "<H5s"
  _CAS_CHANGE_BODY  "<IIqq"
Exchange dividers : observed at connect (SDK audit [S17] §3): 1->100,
  2->100, 3->10000000, 4->100 ... nse_cm = 100.

RAW-WIRE FIELDS DISCARDED BY SDK (NOT exposed on any model)  - VERIFIED/SDK:
  header.seq_no          -> unpacked as _seq_no, discarded   (protocol.py:124)
  header.bitmask_length  -> _bitmask_length, discarded       (protocol.py:125)
  _indicative_close      -> unpacked, unused                 (protocol.py:304)
  _trading_status        -> unpacked, unused                 (protocol.py:307)
  _market_cap (index)    -> unpacked, unused                 (protocol.py:180)
  These never reach the repo. Verified by live wire decode in [S17] §4.

  source "kotak_neo_sfeed".

9. MARKET-DEPTH AUDIT
================================================================================
  - Depth rows structurally: DepthLevel{quantity,price,orders} (models.py:142).
  - Wire: rows after byte 144, 16 B each, count = buy_depth_count +
    sell_depth_count except level 4 forces 1+1 (protocol.py:328-345).
  - L4 touch-line: buy/sell = exactly 1 row. VERIFIED live ([S20] 3509 msgs,
    100% touch_line; 50/50 docs exactly 1 item each; buy[0] price=90.0,
    sell[0] 61.56 examples; bp/bq/sp/sq derived from row 0).
  - L8 depth: 5+5 real rows, prices matched the Quote API book (SDK audit
    [S17] §6). VERIFIED on WIPRO trial (2026-09-15).
  - L16 full depth: ACK-accepted; delivered static ref snapshot with 0+0 rows,
    volume=0, tbv/tsv=0, last_trade_time=0 (method 32 zero pad bytes) in two
    capture windows. VERIFIED NOT available for this account on 3.0.6.
  - App-level: the running system subscribes L4 for ALL instruments because
    the instrument master has ZERO isDepth instruments ([S20] §6). The engine
    route currently active: only data_saver FULL_RAW P0 (status active_consumers=1).
  - Live depth claim in older report [S21] ("buy/sell depth DIRECT_FROM_KOTAK
    (L8)") was corrected by [S20]: observed L4 only. Documented caveat.

18. GAPS / DISCREPANCIES / RISKS / RECOMMENDATIONS
================================================================================
  G1  BUG (field alias)      : storage.py:68 `bs: sq` stores ASK qty under a
      legacy key that downstream pcd-style consumers read as bid-side.
      [S20] §20.3 flagged it. Recommended fix: `bs` = bid quantity (bq) or
      drop the key; document the rename in CHANGELOG before any consumer
      relies on it. (Source-audit finding; remains a live quirk.)
  G2  seq_no / trading_status / indicative_close / market_cap never expose:
      broker provides seq_no on the wire header only - NOT VERIFIED app-side;
      trading_status/indicative_close/market_cap are unpacked + dropped by the
      SDK. If microstructure features need them, the SDK protocol.py must be
      patched (copy _trading_status/_indicative_close onto the models) or the
      repo must decode the raw binary itself - a real capability gap vs the
      344 field schema's F/G/H categories.
  G3  Feed-level mismatch    : production subscribes L4 touch-line for every
      instrument (master has 0 isDepth). L8 depth (5+5) is proven available
      ([S17]) but unused; L16 is ACK-only/static on this account. If the
      feature engine needs depth/order-book features, mark a watchlist subset
      isDepth=true and route them via subscribe_depth.
  G4  No SFeedIndex / MarketStatus in the running process : index/market-context
      fields (K-category) stay unobserved live; subscribing indices / exchange
      broadcast (subscribe_exchange) is required before those WS_CONDITIONAL
      fields can be VERIFIED live.
  G5  L16 static-snapshot risk: relying on subscribe_full_depth for live book
      would silently yield stale/zero data (two-window [S17]); treat L16 as
      unsupported for this account + SDK version.
  G6  sec/docs drift         : architecture.md/consumer-contract describe the
      pipeline accurately, but "buy/sell depth (L8)" claim in [S21] Level 1
      report is not the production reality (L4) - [S20] already corrected it.
  G7  Raw blob memory bound  : PreservedRawStore is 20,000 entries in-memory
      (canonical.py:231); deep raw forensics beyond that window need the Mongo
      `raw` field (kept), not the store.
  G8  Frontend surface tiny  : UI consumes only symbol/ltp/close/volume/ts;
      the persisted superset is not yet used by any page (opportunity, not bug).
  G9  Two backend instances live (earlier session: PIDs 9032 & 13084 on 8000 -
      PID 9032 served these queries) - avoid stale-instance divergence; only
      one should own the session + socket.
