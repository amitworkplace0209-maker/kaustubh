13. TIMESTAMP ANALYSIS
-----------------------
Broker event timestamp (ts): 2026-09-16 09:00:00 IST
Server receive time (receivedAt): 2026-09-16 03:30:00.579 UTC (= 09:00:00.579 IST)
Mongo insertion time: ~0.02s after server receive

The `ts` field uses the broker's last_trade_time/last_update_time epoch value.
The `receivedAt` uses when the server received the message.

Timestamp discrepancy: The broker timestamp `ts` shows 09:00:00 IST exactly,
while receivedAt shows 09:00:00.579 IST. This ~579ms difference is the
network transit time from broker to server.

Note: last_trade_time is often 0 in pre-market data, while last_update_time
contains the actual epoch timestamp. The system uses last_trade_time or
last_update_time (whichever is non-zero) as the broker_timestamp.

1. FEED LEVEL MISMATCH: The system subscribes to L4 touch-line for ALL 8
   instruments, NOT L8 depth. The instrument master has zero `isDepth`
   instruments. This is a configuration gap, not a data loss.

2. PRE-MARKET DATA: All 3,509 messages are pre-market auction data.
   The market opens at 09:15 IST, so 09:00-09:12 is pre-open phase.
   CAS fields (ref_price, imbalance_qty) are present in 36% of messages,
   indicating auction data is being received.

3. 100% FIELD COVERAGE: All 48 top-level storage fields are present in
   100% of documents (50/50 sample). No missing fields.

4. RAW BLOB PRESERVATION: 100% of documents contain the full raw SFeedScrip
   blob with all 31 original fields. No data is lost.

5. TOUCH-LINE ONLY: Buy and sell arrays each contain exactly 1 item
   (touch-line). No L8 depth with 5 levels was observed.

6. ZERO LAST_TRADE_TIME: `last_trade_time` is 0 in all pre-market messages.
   The system uses `last_update_time` (epoch) as the actual timestamp.

7. CAS FIELDS PARTIAL: ref_price, imbalance_qty, imbalance_qty_at_market
   appear in 36% of messages (18/50), indicating they are only present
   during pre-open auction phase, not during regular trading.

8. NO MARKET STATUS MESSAGES: status_code, status, index_name are absent
   because no SFeedMarketStatus or SFeedIndex messages are received
   during this window.

20. RECOMMENDATIONS
--------------------
1. TO GET L8 DEPTH: Mark instruments with isDepth=true in the instrument
   master and ensure subscribe_depth() is called for those instruments.
   Currently, ALL instruments are subscribed via subscribe_scrips() which
   returns L4 touch-line.

2. CAS FIELD HANDLING: The pre-open auction fields (ref_price, imbalance_qty)
   should be explicitly handled and stored separately since they are only
   present during auction phases (36% of messages).

3. BUG: `bs` field equals `sq` (sell quantity). This appears to be an
   alias or bug in storage.py. `bs` should probably be buy-side quantity
   or a separate field.

4. LAST_TRADE_TIME ZERO: During pre-market, last_trade_time is 0. The
   system should use last_update_time as the primary timestamp when
   last_trade_time is 0 (already implemented in canonicalize()).

21. LIMITATIONS
----------------
1. This audit covers ONLY the 09:00-09:12 IST window on 2026-09-16.
   Data from other windows may differ.

2. The instrument master has 9,858 instruments but only 8 received
   data during this window. The other instruments may have different
   subscription patterns.

3. No live Kotak credentials were used. This audit uses production
   MongoDB data that was already captured by the running system.

4. The `raw` blob is preserved in memory (PreservedRawStore, 20,000 max
   entries) and in MongoDB. Raw blob content may have changed since
   this audit if the store was pruned.

5. The `receivedAt` range extends to 03:45:00 UTC because some messages
   were received after the window closed (network latency).
