14. RAW PAYLOAD POLICY
----------------------------------------------------------------------------------------------------
The raw broker payload is preserved SEPARATELY and is NEVER mixed into the canonical
object as duplicate semantic fields.
  canonical object  : raw.reference = 'preserved|<md5(12)>'  (immutable digest)
  raw store         : PreservedRawStore keeps the decoded raw blob (canonical.py:229-244);
                      Mongo tick doc additionally stores the raw decoded blob + raw_reference
  wire bytes        : NOT persisted in production (SDK on_raw never wired in ws_manager --
                      CODED GAP; raw-bytes evidence captured only by isolated probes under
                      docs/reports/kotak_wipro_live/evidence_raw_*.jsonl)
  policy            : canonical consumers read ONLY canonical fields; debugging/replay use
                      the raw envelope/bucket; unknown future wire fields are surfaced via
                      adapter validation, never silently dropped and never guessed.

15. DERIVED FIELD POLICY
----------------------------------------------------------------------------------------------------
PRIMARY (broker direct): everything in identity/price/trade/volume/change/open_interest/
time/depth except the fields below.
DERIVED (computed, EXPLICITLY labelled, single representation per semantic value):
  best_bid_price / best_bid_quantity   : buy[0].price / buy[0].quantity
  best_ask_price / best_ask_quantity   : sell[0].price / sell[0].quantity
  spread                               : best_ask_price - best_bid_price
  mid_price                            : (best_bid_price + best_ask_price) / 2
  buy_sell_volume_ratio                : buy_volume_today / max(sell_volume_today,1)
  exchange_name (identity)             : map from exchange_segment
RULE: no *second* representation of an existing semantic value is created; the probe's

----------------------------------------------------------------------------------------------------
  RAW KOTAK L8 -> DECODE(SDK) -> canonicalize -> build_from_canonical() ->
  VALIDATE -> NORMALIZE(type/unit/timestamp) -> SEMANTIC DEDUPLICATION(alias groups) ->
  CANONICALIZATION(sections) -> MASTER CANONICAL -> (envelope + TICK_VALIDATED.masterCanonical)
  responsibilities: broker-specific mapping (alias table), type/unit normalization,
  timestamp normalization, semantic dedup, depth normalization (variable length), field
  validation, missing-field handling (None, never 0), unexpected-field detection
  (source_keys), schema versioning, feed-level metadata, raw payload preservation
  (separate envelope). Pure functions: no broker I/O, no DB writes.
  ENGINE WIRING (engine.on_feed_message): opt-in flag master_canonical_enabled
  (default OFF), set_master_canonical_enabled(True) activates; canonical object attached
  to the persisted envelope AND to the flat handoff tick under masterCanonical.
