RECOMMENDATIONS / NOTABLE FINDINGS (audit only - no business-logic changes made)
========================================================================================================================
  1. identity fields that are NOT in the SFeed (instrument_type, isin, company_name, series,
     lot_size, tick_size) must come from a master/quote join. The repo master (nse_cm) proves
     isin/companyName/series/instrumentType/lotSize/tickSize exist; the engine should join on
     token/exchange_segment at subscribe time.
  2. previous_day_high/low/volume and previous_open_interest are marked QUOTE_REST_ONLY by the
     existing audit but nothing in the repo parses these keys and no live quote response is
     captured -> MUST be live-verified once credentials exist (CHECK stayed NOT VERIFIED).
  3. expiry / strike_price / currency / option_type: not present in the repo nse_cm master;
     scrip master (REST CSV) or a live quote /all capture is required. nse_fo master must be
     downloaded for F&O identity.
  4. depth fields bid2-5/ask2-5 (and total depth sums) only arrive when a LEVEL 8 (subscribe_depth)
     subscription is active; current runtime subscribes scrips(level4)+index+depth(-flagged tokens).
  5. trading_session / trading_status come from SFeedMarketStatus which requires subscribe_exchange()
     verification.py notes it was NOT subscribed in the historical session. Also protocol.py discards
     the per-instrument trading_status bit -> only exchange-level status is available.
  6. implied_volatility is NOT on the WS feed and is not confirmed in quote REST -> currently
     NOT_AVAILABLE_FROM_KOTAK; if required, needs a live option-chain/quote check before claiming.
  7. settlement_price: not on the feed; NOT_AVAILABLE_FROM_KOTAK for live market data.
  8. sequence_number: wire header seq_no is discarded by protocol.py -> would need SDK change.
  9. sector / industry: genuinely NOT VERIFIED - a taxonomy source must be chosen (NSE segment,
     BSE/S&P sector maps, etc.) before any claim.
  10. The 344-file's own statuses and the report RESULT differ by design: fields.py only judges
      SFeed availability + asserts REST keys; this report's RESULT is the 5-way Kotak-source
      classification and keeps REST-only claims at CHECK=NOT VERIFIED without live proof.
