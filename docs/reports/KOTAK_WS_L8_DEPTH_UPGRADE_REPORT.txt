1. OBJECTIVE & SCOPE
--------------------------------------------------------------------
Replace the active Kotak market-data feed from L4 touch-line to L8 depth on
the existing pipeline, end-to-end, with zero field loss and without any
architectural redesign or parallel WebSocket implementation. L4 is no longer
the active or default level anywhere. Secondary defects discovered along the
way were fixed where in-scope (most notably the storage-doc bs=sq bug).

Pipeline in one line:
  cash equities (db.stocks) -> session-manager desired subscriptions ->
  engine registry -> ws_manager (single SDK SFeedWebSocket owner) ->
  subscribe_depth (L8) -> SFeedScrip(level=8) decode -> canonical adapter ->
  Data Saver -> connection-engine persistence drain -> storage doc ->
  DBWriter -> Mongo db.ticks -> SSE / read APIs -> frontend.
  (Feature Engine receives the same canonical payload as a separate
   TICK_VALIDATED channel; persistence does NOT pass through it.)

4. RAW TICK WIRE FORMAT (protocol)
--------------------------------------------------------------------
L8 depth arrives as message_code 3401 ("depth"), decoded by the SDK to
SFeedScrip with level==8. subscription acks (1109) resolve trading_symbol.
Level semantics (from models.py / protocol.py):
  Level.2  touch line    -> SFeedScrip buy/sell 1+1
  Level.4  touch line    -> SFeedScrip buy/sell 1+1  (legacy active level)
  Level.8  depth         -> SFeedScrip buy/sell 5+5  <== ACTIVE NOW
  Level.16 full depth    -> SFeedScrip buy/sell 16+16 (supported, unused)
market-data exchange channel (subscribe_exchange) and CAS messages
(subscribe_scrips/depth) remain untouched.

6. NORMALIZATION LAYER (canonical.py) - lossless
--------------------------------------------------------------------

7. CLASSIFICATION & ROUTING (ws_manager._group_intents)
--------------------------------------------------------------------
Classification now returns a 4-tuple (scrips, indices, full_depths, depths):
  isIndex / feed-level INDEX        -> indices        (subscribe_index)
  L16 / feed-level 16               -> full_depths    (subscribe_full_depth)
  L8 / feed-level 8 / isDepth       -> depths         (subscribe_depth)
  explicit L1/L2/L4/TOUCH_LINE      -> scrips         (subscribe_scrips;
                                                       legacy explicit only)
  anything else (unclassified)      -> depths         (subscribe_depth)
The default for an unlabelled equity token is now DEPTH (L8). No production
path emits the legacy explicit-script classification anymore (registry,
session-manager, master, engine all default L8). Feed bookkeeping
(_record_feed_level) records index subscriptions as "INDEX", default as
"L8"; feed_levels() = {"L4","L8","L16","INDEX"}.

--------------------------------------------------------------------
8. REGISTRY & MERGE SEMANTICS (registry.py) - depth wins
--------------------------------------------------------------------
RegistryEntry.market_data default "L8". Merge (_tier_of with tier-max of
entry tiers + default 8) means:
  * depth subscription can never be downgraded by an L4 pin;
  * feed_level is kept consistent with the winning tier;
  * marketData is ALWAYS emitted in the token dict (no longer omitted when
    "L4"); is_depth = not index and tier >= 8.
Explicit historical L4 pins remain legal input (classified to legacy scrips)
but nothing in the active pipeline emits them.

--------------------------------------------------------------------
9. SESSION-MANAGER FEED-LEVEL POLICY (refresh_desired_subscriptions)
--------------------------------------------------------------------
When desired subscriptions are rebuilt from db.stocks each day:
  * equity rows are promoted to isDepth=True, feed_level=8 (if feed_level not
    already 8/16), marketData="L8";
  * L16 rows are preserved (marketData="L16");
  * index rows -> isIndex=True, isDepth=False, feed_level=None,
    marketData="INDEX".
_sanitize_feed_level accepts {4,8,16} for compatibility with stored values;
the promotion block overrides 4 -> 8.

    fallback) -> all switched to L8 while keeping legacy explicit

    is now always emitted; depth-wins merge prevents L4 pins downgrading.
  * master JSON carried 9,837 rows defaulted to L4 -> re-seeded to L8.

20. RISKS & RECOMMENDATIONS
--------------------------------------------------------------------
  * L4 now exists only as explicit-input compatibility in classification and
    _sanitize_feed_level {4,8,16}; nothing emits it. Recommend leaving the
    compatibility in place (older stored rows resolve without downgrades).
  * Two uvicorn processes were found this morning on port 8000 (one bare
    `uvicorn app:app` bypassing the singleton guard). Use ONLY
    `run_backend.cmd` / `start_backend.py`; the launcher's single-instance
    guard prevents duplicate lifespan sidecars.
  * Depth rows 2..5 increase storage: ~2x rows/field volume per tick vs
    touch-line. bulk_insert_size=1000 + buffer 5000 absorbed ~7 t/s easily
    (buffer 0, write errors 0). Monitor db size growth on heavy days.
  * The scheduler catch-up proved restart-safe mid-session today (login
    at 08:50 stayed COMPLETED; WS session re-established at 13:33 via stored
    session); avoid restarts in the 15:16-16:00 square-off/logout window.
  * Consider exposing feed_levels() + feedLevelCounts in /api/websocket
    /status for future deterministic assertions without Mongo access.
